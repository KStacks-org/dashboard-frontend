# KStacks Dashboard — Frontend

The dashboard's web client: a **plain Vite SPA** (React 19, TanStack Router,
Paraglide i18n). There is no SSR server — `vite build` emits a directory of
static files, which the image serves with `serve`.

> This is the **planner-frontend** shape, not the portal-frontend /
> groups-frontend one. Those are TanStack **Start**, build to `.output/`, and
> run `node .output/server/index.mjs`. Nothing here produces a server bundle.

## Local development

```bash
pnpm install
pnpm dev          # http://localhost:5173, proxies /api -> http://localhost:4100
```

| Script | What it does |
| --- | --- |
| `pnpm build` | paraglide compile → `tsc -b` → `vite build`, into `dist/` |
| `pnpm typecheck` | compiles i18n messages, then `tsc -b` |
| `pnpm lint` | Biome (scoped to `src/**` and `e2e/**`) |
| `pnpm test` | Vitest unit tests |
| `pnpm test:e2e` | Playwright — **cannot run in this repo alone**, see below |

`src/paraglide/` is generated by `pnpm i18n:compile` and is not committed.

## Docker

```bash
docker build -t dashboard-frontend .
docker run --rm -p 3000:3000 dashboard-frontend
```

### Build arguments

Vite inlines `VITE_*` into the client bundle **at build time**, so these are
build args, not runtime env. Setting them on a running container does nothing —
the values are already compiled into the shipped JavaScript.

| Build arg | Default | When to set it |
| --- | --- | --- |
| `VITE_API_BASE_URL` | *(empty)* | Empty means same-origin `/api`, which is what a reverse-proxied deployment wants. Set only if the frontend and API are on different origins. |
| `VITE_AUTH_SERVICE_LOGIN_URL` | *(empty → falls back to `https://api.kstacks.org/auth/login`)* | Only to point at a non-production auth-service. |

```bash
# split-origin example
docker build \
  --build-arg VITE_API_BASE_URL=https://api.dashboard.example.com \
  -t dashboard-frontend .
```

An empty `VITE_AUTH_SERVICE_LOGIN_URL` is deliberately **unset** before
`vite build` rather than passed through as `""`. `src/lib/authService.ts` uses
`??`, which falls back on `undefined` but not on an empty string — passing `""`
would compile the production fallback URL out of the bundle and leave the
sign-in redirect pointing at nothing.

> `.env` is excluded from the Docker build context on purpose. Vite reads it
> during `vite build`, so a developer's local values would otherwise override
> the build args and end up baked into a production image.

### What the image gives the deployment

| | |
| --- | --- |
| Base | `node:24-alpine` (multi-stage; only `dist/` reaches the runtime stage) |
| Port | **3000** (`EXPOSE 3000`) |
| User | non-root — `appuser`, uid **1001**, gid **1001** |
| Healthcheck | `wget --spider http://localhost:3000/` — static files only, so it never fails because the API is down |
| Size | ~248 MB |
| SIGTERM | clean shutdown, exit 0, ~0.4 s |
| Read-only rootfs | supported (`--read-only` verified) |

Client-side routing is handled by `serve -s`: any path that is not a real file
is answered with `index.html`. A deep link like `/tasks` therefore returns 200
on a cold load or refresh. (The same rewrite means a missing `/assets/*.js`
also returns `index.html` rather than a 404 — inherent to `-s`, and identical
to planner-frontend.)

## CI

| Workflow | Purpose |
| --- | --- |
| `.github/workflows/ci.yml` | lint, typecheck, unit tests |
| `.github/workflows/docker-publish.yml` | builds the image; pushes to GHCR on `main`, build-only on PRs, then bumps the tag in `KStacks-org/infra` |

Both `VITE_*` build args are sourced from GitHub repository **variables**
(`vars.*`). Leave them unset for the normal reverse-proxied deployment.

## End-to-end tests

`e2e/` is kept but is **not** wired into CI, and cannot run from this repo as
it stands. The suite still assumes the pre-split monorepo layout:

- `playwright.config.ts` starts `pnpm dev` with `cwd: ".."` to bring up backend
  and frontend together
- `e2e/global-setup.ts` / `global-teardown.ts` shell out to
  `../../backend` — a path outside this repository — to build DB fixtures
- it stands up a mock JWKS server (`e2e/jwksServer.ts`) that the **backend**
  must be pointed at via `AUTH_SERVICE_JWKS_URL` / `AUTH_SERVICE_JWT_ISSUER`

Running it again needs a decision on where these tests should live. Nothing has
been deleted.
